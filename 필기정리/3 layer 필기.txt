1. 백엔드 3계층 아키텍처 (3-Layered Architecture)백엔드 구조는 크게 3개 레이어로 구분되며, 각 계층은 고유한 역할을 가집니다. 계층 간 데이터 전달 시에는 DTO/Entity 객체가 매개변수 및 반환값으로 사용됩니다.   컨트롤러 (Presentation Layer)   주요 역할: 클라이언트의 요청(Request)을 받아 처리하고 적절한 응답(Response)을 반환하는 창구입니다.   원칙: 데이터베이스에 직접 접근하거나 비즈니스 로직(암호화, 검증 등)을 직접 수행하면 안 되며, 서비스 계층으로 작업을 위임(호출)해야 합니다.   서비스 (Business Layer)   주요 역할: 회원가입, 탈퇴 등 핵심 비즈니스 로직 및 기능 전반을 수행합니다.   데이터 가공, 비즈니스 규칙 검증, 암호화, 로그 작성 등의 작업을 거친 뒤 레포지토리와 연동합니다.   레포지토리 (Data Access Layer)   주요 역할: 데이터베이스(DB)와의 실제 통신(CRUD: 저장, 조회, 수정, 삭제)을 전담합니다.   ID 생성 및 고유 식별자 관리, 데이터 목록 반환 등의 저장소 관련 로직을 관리합니다.   2. 응답 방식의 분리: 화면(View) vs 데이터(API)화면 응답 (JSP 등)   브라우저에 화면을 보여주기 위해 RequestDispatcher 등을 이용해 뷰(View/JSP)로 포워딩합니다.   데이터 응답 (API)   뷰를 거치지 않고 요청받은 순수 데이터(DTO/객체) 자체를 직접 응답으로 처리합니다.   3. 서블릿(Servlet)과 톰캣(Tomcat)의 동작 흐름요청 수신: 클라이언트(브라우저)가 URL과 HTTP 메서드(GET, POST 등)로 요청을 전송합니다.   객체 생성: 톰캣(서블릿 컨테이너)이 해당 요청에 맞는 HttpServletRequest와 HttpServletResponse 객체를 새로 생성합니다.   메서드 호출: 톰캣이 URL 매핑에 따라 적절한 컨트롤러(서블릿)를 찾고, 요청 방식에 맞춰 doGet() 또는 doPost() 메서드를 호출하며 생성된 Request/Response 객체를 매개변수로 전달합니다.   계층 간 호출: 컨트롤러는 요청 데이터를 꺼내 서비스 계층을 호출하고, 서비스는 레포지토리를 호출하여 작업을 완료합니다.   응답 구성: 컨트롤러가 Response 객체에 상태 코드(Status Code), 인코딩, 반환 데이터를 설정(Set)합니다.   최종 응답 전송: 메서드 실행이 끝나면 톰캣이 최종 설정된 Response 객체의 정보를 바탕으로 클라이언트에게 응답을 보냅니다.
