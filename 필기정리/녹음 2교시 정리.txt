DBMS와 미들웨어의 개념DBMS (Database Management System):3306(또는 3308) 포트 등으로 실행되는 서버 프로그램(예: MySQL Server)으로, 데이터를 직접 보관하고 관리해 주는 시스템입니다.   미들웨어(Middleware)로서의 역할:애플리케이션(Java 등)과 실제 물리적인 저장 장치(하드웨어) 사이에서 데이터 삽입, 조회, 중계 역할을 담당합니다.   데이터베이스 vs DBMS:데이터베이스(DB)는 데이터의 집합(창고 건물) 자체를 뜻하며, DBMS는 이 창고를 체계적으로 관리해 주는 관리 시스템(프로그램)을 뜻합니다.   2. 서버와 클라이언트(Workbench 등)의 구분MySQL Server: PC 백그라운드에서 상시 구동되며 실제 데이터를 관리하는 서버 프로그램입니다.   클라이언트 도구 (MySQL Workbench, IntelliJ DB 탭, CLI 등):워크벤치 자체가 데이터베이스인 것이 아닙니다.   사용자가 쿼리(SQL)를 타이핑하거나 클릭을 통해 MySQL 서버에 접속하여 작업을 편하게 수행할 수 있도록 돕는 GUI/CLI 클라이언트 도구에 불과합니다.   3. 데이터베이스(DBMS)를 사용하는 이유 (vs 엑셀)대규모 동시 접속 처리:엑셀 파일은 여러 명이 동시에 수정하거나 대규모 사용자가 접근할 때 충돌이 발생하지만, DBMS는 수천~수만 건의 동시 읽기/쓰기 트랜잭션을 안정적으로 처리합니다.   대용량 데이터 성능:수십만~수억 건의 데이터가 쌓였을 때 엑셀은 열람조차 어렵지만, DBMS는 인덱싱 등을 통해 빠르게 처리합니다.   데이터 무결성 및 보안:제약 조건(PK, FK 등)을 통해 잘못된 데이터 입력을 원천 차단하고 정합성을 유지합니다.   실수로 인한 삭제를 방지하고 자동 백업 및 롤백, 트랜잭션 로그 관리 기능을 제공합니다.   4. SQL의 핵심 분류: DDL vs DML (CRUD 관점 비교)모든 프로그램은 CRUD(생성, 조회, 수정, 삭제)로 동작하며, 대상이 구조(틀)이냐 실제 데이터(내용물)냐에 따라 구분됩니다.   구분DDL (데이터 정의어)DML (데이터 조작어)대상데이터가 담길 구조/틀/공간 (창고, 선반, 테이블 등)   틀 안에 들어갈 실제 데이터 (사과, 레코드 등)   C (생성)CREATE (없는 구조/테이블을 새로 만듦)   INSERT (만들어진 틀 안에 데이터를 삽입함)   R (조회)SHOW, DESCRIBE (어떤 구조가 있는지 확인)   SELECT (틀 안의 데이터를 검색/조회)   U (수정)ALTER (컬럼 추가, 타입 변경 등 구조 변경)   UPDATE (기존에 들어있는 데이터 값을 수정)   D (삭제)DROP (테이블/데이터베이스 틀 자체를 날림)   DELETE (틀은 두고 데이터 행만 삭제)
