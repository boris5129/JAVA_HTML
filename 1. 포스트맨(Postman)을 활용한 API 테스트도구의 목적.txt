1. 포스트맨(Postman)을 활용한 API 테스트도구의 목적: 화면(HTML/JSP)이나 자바스크립트(fetch 등) 코드를 작성하지 않고도, 서버 엔드포인트로 직접 HTTP 요청(GET, POST 등)을 전송하여 백엔드 로직이 정상 동작하는지 검증하는 테스트 도구입니다.   워크스페이스 및 컬렉션 설정: 워크스페이스를 생성하고 컬렉션(예: Servlet) 및 환경 변수(예: baseUrl = http://localhost:8080)를 지정하여 요청 주소를 효율적으로 관리합니다.   POST 요청 및 JSON 전송:HTTP Method를 POST로 설정하고 URL(예: {{baseUrl}}/api/products 또는 /api/students)을 입력합니다.   Body 탭에서 raw → JSON을 선택하면, Headers에 자동으로 Content-Type: application/json이 주입됩니다.   JSON 형식의 본문 데이터를 작성한 후 Send를 누르면 서버의 doPost()로 데이터가 전송되며, 정상 처리 시 200 OK 응답을 확인합니다.   2. 백엔드 서블릿 데이터 바인딩 주의점Jackson 역직렬화 시 키값 일치:클라이언트(포스트맨)에서 전송하는 JSON의 Key 이름과 Java DTO(Model) 클래스의 필드명이 대소문자까지 정확히 일치해야 값이 정상적으로 매핑됩니다.   일치하지 않거나 오타가 발생하면 서버 콘솔에 필드값이 null로 들어옵니다.   404 에러의 주원인: 요청 URL에 오타가 있거나 서블릿의 @WebServlet 경로 매핑이 잘못되었을 때 발생합니다.   3. 서블릿 필터(Filter)의 개념 및 동작 원리필터의 필요성:서블릿마다 한글 깨짐 방지를 위해 response.setCharacterEncoding("UTF-8")을 반복 작성해야 하는 등 중복되는 공통 처리 로직을 서블릿 실행 전/후 단계로 분리하기 위해 사용합니다.   필터 구현 방법:jakarta.servlet.Filter (또는 javax.servlet.Filter) 인터페이스를 구현(implements)합니다.   @WebFilter("/api/*")처럼 어노테이션을 달아 특정 URL 패턴으로 들어오는 모든 요청이 필터를 거치도록 설정합니다.   추상 메서드인 doFilter()를 오버라이드하여 공통 로직을 작성합니다.   필터 체인(FilterChain)의 핵심 역할:필터 내부에서 chain.doFilter(request, response)를 반드시 호출해야 합니다.   이 메서드를 호출하지 않으면 요청 흐름이 다음 필터나 최종 목적지인 서블릿(doGet, doPost)으로 전달되지 않고 끊겨 클라이언트에 아무런 응답도 전송되지 않습니다.   chain.doFilter()를 호출해야 서블릿이 실행되고, 서블릿의 메서드 작업이 끝난 뒤 다시 필터로 스택이 되돌아오면서 응답이 완성됩니다.
